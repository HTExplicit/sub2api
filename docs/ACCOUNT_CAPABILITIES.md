# 账号能力与公开模型

管理员入口为 `/admin/account-capabilities`，账号页、分组页和侧栏均提供链接。普通用户不能读取账号成员、真实凭据或内部路由配置。

## 操作顺序

1. 选择来源文件夹并获取新鲜上游目录。创建批次时冻结完整账号 ID；新导入或移出文件夹的账号不会静默混入正在运行的批次。
2. 在主流候选中选择要使用的真实型号和协议，执行一次性验证。目录声明、现有配置、实测结果和已公开状态是四种不同事实。
3. 勾选可发布的成功证据，整理分组草稿，查看完整变更预览后应用。现有名称、倍率、Key、私用映射和非目标组绑定保留。

公开模型名单是整组替换，请把需要继续提供的型号一并纳入草稿。没有可用型号的组保持不对外提供模型，不用静态目录补齐。

## 验证与记录

- 默认总并发 2、同账号并发 1、每个请求 60 秒。文字验证一次发送；显式工具往返最多两次，每次独立限时。
- Responses HTTP、WebSocket、Chat、Messages 记录实际出站协议；客户端入口与上游协议不可混为一谈。计数接口的 `available` 不是推理 `alive`。
- 暂停只停止新领取，已发送项排空。重启后可能已发送但没有回执的项标为不确定，不自动重放；已知次数和可能发送次数分开显示。
- 单个模型不支持、超时、限流、配额耗尽不等于整个账号死亡。只有明确账号级失效证据才可提出关闭调度；调度是全局属性，预览会提示其对专属组的影响。
- 记录长期保留，但发布要求 24 小时内且配置仍一致的证据。完整历史中的后续失败可使旧成功失效；目录重新成功不能替代新的模型验证。
- 不保存认证头、密钥、对话正文或完整上游错误。探测不修改原账号错误、额度或冷却状态。

## 模型与路由

首版默认候选为经审核的主流文字和编程型号，不自动将整个上游目录公开。不同真实上游目标保留为不同候选；同账号同组同公共型号最终只选一个目标，保留该目标所有已验证协议。

普通与 VIP 线路分别编译为组专用内部标识。内部标识不出现在公共模型清单；公开目录直接由当前有效的托管路由成员投影，不为此增加私用账号的标准名映射。

保留的 `s2pub-` 名称空间在全部客户端目录与请求入口隔离，包括共享账号的非托管私用组。普通模型目录、Codex 清单及固定上游目录都隐藏它；HTTP 与 WS 首帧／后续轮次拒绝客户端直接提交该名称。只有托管路由校验后的服务端内部改写可以使用 selector，原私用模型和映射值保持不变。

托管组的名称与合法别名必须唯一匹配已发布路由。未验证的端点、漂移的凭据、代理、绑定或映射会在上游调用前被拒绝。非托管私有组和 Cindy 保持原行为。

调度的轻量缓存保留裁剪前的完整账号身份摘要，不用裁剪后的凭据重新生成判活身份。该摘要只用于筛选；实际发送前仍重新读取完整账号，校验身份、组绑定与精确映射。旧格式缓存回源更新，不需要清空 Redis 或重新执行已完成的判活。

仅托管公开的非 GPT 型号在 Messages 兼容入口省去自动添加的 GPT 推理默认值；DeepSeek V4 的无思考请求按实际 Responses／Chat 协议分别表达。用户显式的思考或 effort 设置、工具选择和已有输出预算规则保留，私用组、Cindy、GPT 及原生 Responses 入口不受此规则影响。型号活性与代表性工具往返验收仍是两种独立证据。

管理员直接编辑已托管组的派生白名单或渠道可能造成配置漂移；请回到能力页重新预览应用，不以关闭白名单绕过托管准入。

## API 与持久化

管理接口位于 `/api/v1/admin/account-capabilities`：

- 根路径和 `/candidates`：读取记录与候选。
- `/runs`：创建和读取目录/验证批次；创建需 `Idempotency-Key`。
- `/runs/:id/items`、`pause`、`resume`、`cancel`：逐项记录与控制。
- `/changesets/preview`、`/changesets/:id`、`/changesets/:id/apply`：预览、读取与幂等应用。

迁移 240 新增能力运行、条目、变更集三张表和默认关闭的分组托管字段。应用通过单一事务、配置比较及持久缓存失效事件提交；冲突不部分写入，不恢复整库。新功能不会自动创建周期性模型测试。
