# 公开模型管理

管理员入口仍为 `/admin/account-capabilities`，账号页、分组页和侧栏均提供链接；账号、分组和来源筛选随入口传递。普通用户不能读取账号成员、真实凭据或内部路由配置。

## 操作顺序

1. 首页按分组查看已开放型号、判活通过账号和待处理事项；默认来源为 `dmxapi`、`白嫖`。进入分组后按型号查看，账号数按账号去重，不随明细分页变化。
2. 整理助手依次展示“发现缺口 → 检查未测部分 → 确认推荐变化”。已有同配置基础成功直接复用；有必要时才显式检查服务端列出的未测组合。开始前显示新增组合数和最多请求数。
3. 检查结束后直接继续生成推荐，确认新增型号、补入账号、保留配置和明确停用项后应用。技术标识、协议及证据详情无需参与基本操作。缺价格显示“判活通过，等待定价”，进入现有渠道定价页面处理。

默认采用补充／合并；未勾选、未显示、暂时失败或历史较久都不是删除意图。移除型号、线路或绑定必须显式提出并在预览中单列。旧整组替换不得静默删除未列出的现有配置。应用前重新比对配置版本，冲突时保留新变化，不覆盖浏览器或其他任务的修改。

默认合并也保留账号的全局接单开关；历史判活成功不会重新启用手动停调度的账号。关闭接单的成功线路可保留在公开配置中，但不计为当前可接单；需要启用时必须另有明确操作意图，不能借整理分组影响私用组。

## 验证与记录

- 默认总并发 2、同账号并发 1、每个请求 60 秒。整理助手只生成一次基础文本判活，不自动运行工具、计数或 WebSocket 验收，不自动重试失败原组合。
- Responses HTTP、WebSocket、Chat、Messages 记录实际出站协议；客户端入口与上游协议不可混为一谈。计数接口的 `available` 不是推理 `alive`。
- 暂停只停止新领取，已发送项排空。重启后可能已发送但没有回执的项标为不确定，不自动重放；已知次数和可能发送次数分开显示。
- 单个模型不支持、超时、限流、配额耗尽不等于整个账号死亡。只有明确账号级失效证据才可提出关闭调度；调度是全局属性，预览会提示其对专属组的影响。
- 最近尝试和最近成功分别保留。同配置基础成功可复用，超过 24 小时只提示历史时间，不强制重测或撤掉公开配置。配置已变化的旧成功不能冒充当前通过；目录声明、计数成功和工具结果不能替代基础判活。
- “已对外开放”“当前可接单账号”“最近判活结果”是独立事实。临时冷却、503、限流和超时只影响对应线路当前状态，不能据单条失败撤掉整个型号；明确型号不支持也不自动停整个账号调度。
- 未测去重依据账号、精确真实目标、接入方式及配置身份；同账号真实目标已有成功时，不为扩展接口覆盖额外补测。无成功时可显式检查此前未测的兼容方式；别名、分组和页面重复选择不会增加请求。
- 不保存认证头、密钥、对话正文或完整上游错误。探测不修改原账号错误、额度或冷却状态。

## 模型与路由

候选来自上游目录、具体配置、历史记录及现有公开配置的并集。主流名单只分类和排序，不静默过滤目录中的型号。Fable 5 与 5.1 等版本分别展示；VIP、SSVIP、CC 等上游名称保持精确，只有明确等价依据才合并为同一公共型号的不同线路，其他名称进入“待确认名称”。可见不等于判活通过，也不自动公开整个上游目录。

托管路由 v2 兼容读取 v1。一个公共型号可含多个平台、真实目标和已验证接入方式；同账号相同真实目标的别名合并，不同真实目标保留备选。接入资格依据已有转发适配器，不按模型厂商排除兼容成功账号。

普通与 VIP 线路保持隔离，使用组专用内部标识。公共目录反映已发布配置，不把当前冷却等同于未发布；当前可接单容量另行计算。既有公共名称、Key、倍率、私用映射及非目标组绑定保持。

保留的 `s2pub-` 名称空间在全部客户端目录与请求入口隔离，包括共享账号的非托管私用组。普通模型目录、Codex 清单及固定上游目录都隐藏它；HTTP 与 WS 首帧／后续轮次拒绝客户端直接提交该名称。只有托管路由校验后的服务端内部改写可以使用 selector，原私用模型和映射值保持不变。

托管组的名称与合法别名必须唯一匹配已发布路由。未验证的端点、漂移的凭据、代理、绑定或映射会在上游调用前被拒绝。跨分支选择仅用于托管公开请求，调用已有单次转发适配器，沿用优先级、并发及重试预算，不重新进入完整请求处理器。输出内容后禁止跨线路重放；账号绑定的续接保持亲和。非托管私用组和 Cindy 原行为保持。

调度的轻量缓存保留裁剪前的完整账号身份摘要，不用裁剪后的凭据重新生成判活身份。该摘要只用于筛选；实际发送前仍重新读取完整账号，校验身份、组绑定与精确映射。旧格式缓存回源更新，不需要清空 Redis 或重新执行已完成的判活。

仅托管公开的非 GPT 型号在 Messages 兼容入口省去自动添加的 GPT 推理默认值；DeepSeek V4 的无思考请求按实际 Responses／Chat 协议分别表达。用户显式的思考或 effort 设置、工具选择和已有输出预算规则保留，私用组、Cindy、GPT 及原生 Responses 入口不受此规则影响。型号活性与代表性工具往返验收仍是两种独立证据。

管理员直接编辑已托管组的派生白名单或渠道可能造成配置漂移；请回到能力页重新预览应用，不以关闭白名单绕过托管准入。

## API 与持久化

管理接口位于 `/api/v1/admin/account-capabilities`：

- 根路径和 `/candidates`：读取记录与候选。
- `/overview`：服务端全量分组／型号聚合，区分公开配置、当前路由和最近证据。
- `/plan`：统一生成未测基础判活请求、增量预览请求、业务影响及未采用原因；调用本身不发模型请求或应用配置。
- `/runs`：创建和读取目录/验证批次；创建需 `Idempotency-Key`。
- `/runs/receipt`：按原幂等键只读查询提交回执；页面刷新或响应不确定不自动创建新批次。
- `/runs/:id/items`、`pause`、`resume`、`cancel`：逐项记录与控制。
- `/changesets/preview`、`/changesets/:id`、`/changesets/:id/apply`：预览、读取与幂等应用。

迁移 240 新增能力运行、条目、变更集三张表和默认关闭的分组托管字段。应用通过单一事务、配置比较及持久缓存失效事件提交；冲突不部分写入，不恢复整库。新功能不会自动创建周期性模型测试。
